## 🏗 АРХИТЕКТУРА

### Конфиг (`config.json`)

**Расположение:** рядом с `chat.py` (определяется через `Path(__file__).parent / "config.json"`).

**Поведение при первом запуске:**

1. Если файл отсутствует — создать шаблон с дефолтными значениями и placeholder'ом для `api_key` (`"sk-YOUR-KEY-HERE"`)
2. Вывести понятную инструкцию: `Конфиг создан: {путь}. Укажите api_key и запустите снова.`
3. Завершить работу с кодом `0`

**Валидация при каждом запуске:**

- Если JSON невалиден → сообщение с номером строки ошибки парсинга
- Если обязательное поле отсутствует → `Ошибка конфига: отсутствует поле "api_key"`
- Если тип значения неверный → `Ошибка конфига: поле "temperature" должно быть числом, получено "high"`
- **Обязательные поля:** `api_key`, `api_base`, `default_model`
- Остальные поля имеют дефолтные значения при отсутствии

**Формат:**

```json
{
  "api_key": "sk-...",
  "api_base": "https://api.openai.com/v1",
  "default_model": "gpt-4o",
  "system_prompt": "Ты полезный ассистент.",
  "render_markdown": false,
  "generation": {
    "temperature": 0.7,
    "top_p": 1.0,
    "max_tokens": 4096
  },
  "models": [
    {
      "id": "gpt-4o",
      "name": "GPT-4o",
      "context_window": 128000,
      "input_price_per_1m_tokens_rub": 150.0,
      "output_price_per_1m_tokens_rub": 600.0
    },
    {
      "id": "deepseek-reasoner",
      "name": "DeepSeek R1",
      "context_window": 65536,
      "supports_thinking": true,
      "input_price_per_1m_tokens_rub": 3.0,
      "output_price_per_1m_tokens_rub": 15.0
    }
  ]
}
```

**Дефолты для необязательных полей** (если отсутствуют в конфиге):

| Поле | Дефолт |
|---|---|
| `system_prompt` | `"Ты полезный ассистент."` |
| `render_markdown` | `false` (по умолчанию ответ выводится как обычный текст) |
| `generation.temperature` | `0.7` |
| `generation.top_p` | `1.0` |
| `generation.max_tokens` | `4096` |
| `models` | `[]` (список пуст — стоимость не считается, но чат работает) |
| `models[].supports_thinking` | `false` |
| `models[].context_window` | `128000` |

> **Изменение `default_model` из программы:** команда `/model <модель> --default` обновляет поле `default_model` в `config.json`
> (с сохранением форматирования и остальных полей), делая выбранную модель моделью по умолчанию для последующих запусков.

### История ввода (`./.input_history`)

**Расположение:** `Path(__file__).parent / ".input_history"` — отдельный файл рядом с программой.

- Используется `prompt_toolkit.history.FileHistory` для **персистентного хранения истории ввода между запусками** программы.
- История доступна через ↑/↓ и используется для автозавершения (см. раздел ВВОД).

### Глобальная статистика токенов (`./usage_stats.json`)

**Расположение:** `Path(__file__).parent / "usage_stats.json"`. Создаётся автоматически.

- Ведётся **суммарная статистика всех использованных токенов за все сессии** (накопительно).
- Обновляется после каждого полного ответа ассистента.
- Формат:

```json
{
  "total_prompt_tokens": 152340,
  "total_completion_tokens": 89210,
  "total_cost_rub": 42.18,
  "total_requests": 318,
  "updated_at": "2026-05-27T10:44:51"
}
```

- Отображается в команде `/usage` (см. раздел КОМАНДЫ): помимо статистики текущей сессии — отдельный блок «За всё время».

### История сессий (`./history/`)

**Расположение:** `Path(__file__).parent / "history"`. Создаётся автоматически.

Каждая сессия — отдельный JSON-файл.
**Имя файла:** `YYYYMMDD_HHMMSS.json` (по моменту создания сессии).

**Автосохранение:** после каждого полного ответа ассистента (и при `/new`, `/exit`, `Ctrl+C`).

**Формат файла:**

```json
{
  "session_id": "20231027_153000",
  "created_at": "2023-10-27T15:30:00",
  "default_model": "gpt-4o",
  "total_tokens": 37,
  "messages": [
    {
      "role": "system",
      "content": "Ты полезный ассистент.",
      "timestamp": "2023-10-27T15:30:00"
    },
    {
      "role": "user",
      "content": "Привет!",
      "timestamp": "2023-10-27T15:30:05"
    },
    {
      "role": "assistant",
      "content": "Здравствуйте! Чем могу помочь?",
      "model": "gpt-4o",
      "timestamp": "2023-10-27T15:30:07",
      "thinking": "Пользователь поздоровался, нужно ответить приветливо...",
      "usage": {
        "prompt_tokens": 25,
        "completion_tokens": 12
      }
    }
  ]
}
```

> **Примечание:** поле `thinking` сохраняется только если модель вернула `reasoning_content`. При загрузке истории `thinking` **НЕ** отправляется обратно в API — это только для отображения.
> Поле `total_tokens` хранит суммарное количество токенов сессии (prompt + completion) — используется в столбце таблицы `/history`.

### Режимы вывода ответа

Клиент поддерживает **два режима** отображения текста ответа модели:

1. **Plain text** (по умолчанию) — исходный текст без какой-либо обработки. Markdown-разметка (`` ` ``, `#`, `-`, `\`) выводится как есть. Никаких преобразований таблиц, списков, кода. Используется `console.print(text, markup=False, highlight=False)`.
2. **Markdown** — рендеринг через `rich.markdown.Markdown`. Включается, если `render_markdown: true` в конфиге или включён командой `/markdown on` в текущей сессии.

> Режим переключается **на лету**. Уже выведенные ответы **не перерисовываются** — изменение применяется только к следующим. Состояние режима — runtime-флаг внутри `ChatUI`, **не сохраняется** в файл сессии.

#### Заголовок ответа

```
🤖 claude-opus-4-7
```

- Префикс `🤖 ` + `name` модели (или `id`), стиль `bold green`.

#### Строка статистики ответа

```
⏱ Токены: ↑50 ↓21 │ 💰 0.0009₽ │ ⏳ 3.5с
```

- `↑` — prompt tokens, `↓` — completion tokens
- `💰` — стоимость в рублях (если модель не в списке `models` — показывать `—`)
- `⏳` — затраченное время
- Для моделей с thinking добавляется reasoning-токены: `⏱ Токены: ↑250 ↓340 (💭120) │ ...`

#### Ответ модели с thinking (для моделей с `supports_thinking: true`)

```
💭 Размышляю...
   Нужно разобрать вопрос пользователя...
   Сначала проверю основные факты...
   [мысли отображаются тусклым серым, стримятся в реальном времени, всегда plain text]

🤖 DeepSeek R1

Финальный ответ модели (рендеринг зависит от режима markdown).

⏱ Токены: ↑250 ↓340 (💭120) │ 💰 0.05₽ │ ⏳ 5.3с
```

> Блок `thinking` **всегда** выводится как plain text (тусклый курсив), независимо от режима markdown.

### Live-статистика во время стриминга

**Весь текст ответа выводится в реальном времени во время стриминга** (а не только в конце). Строка статистики отображается под текущим потоком текста и обновляется на каждый chunk:

```
⏱ Токены: ↑125 ↓73... │ 💰 ~0.02₽ │ ⏳ 1.2с
```

- **125** — prompt tokens (известны после первого chunk'а из `usage` или подсчитаны заранее)
- **73** — completion tokens (растут в реальном времени, считаем чанки)
- **`...`** после числа — индикатор что генерация продолжается
- **`~`** перед стоимостью — приблизительно (до завершения)
- После завершения `...` и `~` убираются, показываются финальные значения

### Цветовая схема

| Элемент | Стиль Rich |
|---|---|
| Заголовок панели запуска | `bold cyan` |
| Заголовок ответа ассистента (`🤖 ...`) | `bold green` |
| Текст ответа в режиме plain | default (без стилей и подсветки, без markup) |
| Текст ответа в режиме markdown | Рендеринг через `rich.markdown.Markdown` |
| Thinking/reasoning | `dim italic` (всегда plain, независимо от режима) |
| Системные сообщения/info | `dim` |
| Статистика | `dim cyan` |
| Ошибки | `bold red` в панели с заголовком «Ошибка» |
| Команды в `/help` | `bold yellow` |

### Визуальное разделение

Между сообщениями — `rich.rule.Rule(style="dim")` (горизонтальная линия на всю ширину).

## ⌨️ КОМАНДЫ

| Команда | Описание | Детали поведения |
|---|---|---|
| `/new` | Новый разговор | Сохранить текущую сессию → сбросить контекст → создать новую сессию. Показать подтверждение: `Сессия сохранена. Новый разговор начат.` |
| `/new --clear` | Новый разговор + очистка экрана | То же, что `/new`, но дополнительно вызывает `console.clear()` и перерисовывает баннер |
| `/history` | Список сохранённых чатов | Показать таблицу: №, дата, модель, первое сообщение пользователя (до 60 символов), **столбец «Токены» справа** (`total_tokens` сессии). Ввод номера → загрузить сессию. Enter без номера → отмена. Пагинация: последние 20, `/history all` — все |
| `/history <session_id>` | Загрузить конкретную сессию | `/history 20260527_104451` — загрузить сессию по `session_id` (имени файла без `.json`). Если не найдена — `Сессия {id} не найдена` |
| `/model` | Выбор модели | Пронумерованный список из `config.models`. Ввод номера → переключение. Показать подтверждение: `Модель переключена на {name}` |
| `/model <имя или №>` | Быстрое переключение | Поиск по `id` или `name` (case-insensitive, частичное совпадение). Если совпадений >1 — показать список. Если 0 — `Модель не найдена` |
| `/model <модель> --provider <провайдер>` | Смена модели и провайдера | Одновременно переключить модель и сменить провайдера (api_base/api_key из соответствующей записи провайдера, если поддерживается конфигом, либо обновить активный `api_base`). Подтверждение: `Модель переключена на {name}, провайдер: {provider}` |
| `/model <модель> --default` | Сделать моделью по умолчанию | Переключить модель И записать её `id` в `default_model` файла `config.json`. Подтверждение: `Модель {name} установлена по умолчанию.` |
| `/markdown` | Показать состояние рендеринга | Вывод: `Markdown-рендеринг: ВКЛ` или `Markdown-рендеринг: ВЫКЛ` |
| `/markdown on` / `/md on` | Включить markdown | Подтверждение: `Markdown-рендеринг включён.` |
| `/markdown off` / `/md off` | Выключить markdown | Подтверждение: `Markdown-рендеринг выключен.` |
| `/markdown toggle` / `/md` | Переключить режим | Инвертирует текущее состояние, выводит новое значение |
| `/file <путь>` | Отправить файл | Прочитать текстовый файл (UTF-8), показать превью (первые 3 строки + размер), спросить подтверждение. Отправить содержимое как сообщение пользователя. Если файл не найден / не текстовый / слишком большой (>100KB) — понятная ошибка |
| `/clear` | Очистить экран | `console.clear()`. Контекст сохраняется. Показать баннер заново |
| `/usage` | Статистика | Два блока: **«Текущая сессия»** (prompt/completion токены, стоимость, число запросов, средняя стоимость запроса) и **«За всё время»** (из `usage_stats.json`: суммарные токены, суммарная стоимость, всего запросов) |
| `/help` | Справка | Таблица команд Rich. Включить информацию о многострочном вводе (Ctrl+Enter) и о режиме markdown |
| `/exit` | Выход | Сохранить сессию → `До свидания!` → `sys.exit(0)` |

**Алиасы команды markdown:** `/markdown` и `/md` — полные синонимы. Аргументы `on`/`off`/`toggle` регистронезависимы. Без аргумента — `/markdown` показывает состояние, `/md` переключает (для удобства).

**Обработка неизвестных команд:** если ввод начинается с `/` и команда не распознана — `Неизвестная команда: {cmd}. Введите /help для справки.` (**НЕ** отправлять в API).

## 🚀 CLI-ФЛАГИ

| Флаг | Описание |
|---|---|
| `--markdown` / `-m` | Принудительно включить markdown-режим на старте (переопределяет `render_markdown`) |
| `--no-markdown` | Принудительно выключить markdown |
| `--debug` | Полный traceback ошибок в stderr |
| `--history <session_id>` | Открыть сохранённую сессию из командной строки при запуске. Пример: `python chat.py --history 20260527_092354` |
| `--input <text_file.txt>` | Считать содержимое текстового файла как запрос пользователя, отправить его |
| `--output "<текст запроса>"` | **Неинтерактивный режим:** отправить указанный текст в модель, вывести ответ в консоль (stdout) и завершить работу. Программа НЕ запускает интерактивный цикл. Полезно для скриптов/пайпов |

> При совместном использовании `--input`/`--output` и `--history` — сессия загружается как контекст, затем выполняется запрос.
> Режим `--output` выводит только ответ модели (без панелей и баннера, если не указано иное), пригодный для пайпинга.

## ⚠️ ОБРАБОТКА ОШИБОК

| Ситуация | Поведение |
|---|---|
| Сетевая ошибка / таймаут | Retry до 3 раз с экспоненциальной задержкой (1с, 2с, 4с). Прогресс: `Повторная попытка 2/3 через 2с...` |
| HTTP 401 | `Неверный API-ключ. Проверьте поле api_key в config.json` (без retry) |
| HTTP 429 | Извлечь `Retry-After` из заголовков. `Превышен лимит. Повтор через {N}с...`. Автоматический retry |
| HTTP 400 (context length) | `Превышен контекст модели ({window} токенов). Используйте /new для нового разговора.` Предложить автоматическую обрезку: `Удалить старые сообщения и повторить? (y/n)` |
| HTTP 500+ | `Ошибка сервера ({code}). Повтор...` + retry |
| Невалидный JSON конфига | `Ошибка парсинга config.json (строка {N}): {описание}` |
| Отсутствующее обязательное поле | `Ошибка конфига: отсутствует обязательное поле "{field}"` |
| Неверный тип поля | `Ошибка конфига: поле "{field}" должно быть {expected}, получено {actual}` |
| Модель из `default_model` не найдена в `models` | Предупреждение (не ошибка): `Модель {id} не найдена в списке models. Стоимость не будет рассчитываться.` |
| Файл не найден (`/file`, `--input`) | `Файл не найден: {путь}` |
| Ошибка кодировки файла | `Не удалось прочитать файл: {ошибка}. Убедитесь что файл в кодировке UTF-8.` |
| Сессия для `/history <id>` / `--history` не найдена | `Сессия {id} не найдена` |

**Все ошибки:**

- Выводятся через `rich.panel.Panel` с красной рамкой
- **Никогда** не показывают traceback пользователю
- Логируются в `stderr` для отладки (опционально: `--debug` флаг для полного traceback)

## ⌨️ ВВОД (prompt_toolkit)

**Конфигурация prompt_toolkit:**

- `Enter` — перевод строки (новая строка внутри сообщения)
- **`Ctrl+Enter` — отправка сообщения** (основной хоткей отправки)
- `↑`/`↓` — навигация по **персистентной истории ввода** (`FileHistory` → `./.input_history`), только когда курсор на первой/последней строке
- `Ctrl+V` / `Shift+Insert` — корректная вставка многострочного текста из буфера
- **При вставке многострочного текста из буфера — отображать не более 30 строк** (если больше — показать первые 30 строк + индикатор `… ещё N строк`), при этом в сообщение уходит полный текст
- **Автозавершение ввода:** использовать автодополнение
  - из **истории ввода** (предыдущие запросы пользователя)
  - для **команд** (список `/new`, `/history`, `/model`, `/markdown`, `/md`, `/file`, `/clear`, `/usage`, `/help`, `/exit` и их аргументов: `on/off/toggle`, `--provider`, `--default`, `--clear`, `all`)
  - реализовать через `prompt_toolkit.completion` (например, `Completer`/`merge_completers`, история через `AutoSuggestFromHistory` или кастомный completer)
- Пустое сообщение (только пробелы/переводы строк) — не отправляется, тихо игнорируется

**Подсказка при первом запуске:** под промптом показать dim-текст: `(Ctrl+Enter — отправить, /help — справка, /md — markdown ВКЛ/ВЫКЛ)`. Скрыть после первой отправки.

## 📡 СТРИМИНГ И ПОДСЧЁТ ТОКЕНОВ

### Стриминг

- Использовать `client.chat.completions.create(stream=True)`
- Обрабатывать `stream_options={"include_usage": True}` если API поддерживает (`try/except`)
- Для моделей с `supports_thinking` — обрабатывать `delta.reasoning_content` отдельно от `delta.content`
- Использовать `rich.live.Live` для обновления вывода в реальном времени
- **Весь текст ответа выводится во время стриминга** (полный накопленный текст обновляется на каждый chunk)

### Логика рендеринга в Live:

- **Если markdown ВЫКЛ** (по умолчанию): на каждом chunk обновлять `Live` содержимым `Text(accumulated, no_wrap=False)` без markup и подсветки.
- **Если markdown ВКЛ:** пересобирать `Markdown(accumulated)` на каждый chunk и обновлять `Live`.
- Блок `thinking` **всегда** рендерится как `Text` со стилем `dim italic`, независимо от режима.

> **Важно:** при plain-режиме никакая интерпретация символов (`` ` ``, `#`, `\`, `[]`) не выполняется — пользователь видит ровно то, что вернул API.

### Подсчёт токенов

- **Приоритет:** данные из `usage` в ответе API (последний chunk при stream)
- **Fallback:** если API не вернул `usage` — грубая оценка: `len(text) / 4` для английского, `len(text) / 2` для текста с кириллицей
- **Стоимость:** рассчитывать по ценам из `config.models` для текущей модели
- Если модель **не в списке** `models`: токены считать, стоимость показывать как `—`
- **После каждого ответа** — обновлять `usage_stats.json` (накопительная статистика всех сессий) и `total_tokens` в файле текущей сессии

### Формула стоимости

```
cost = (prompt_tokens × input_price / 1_000_000) + (completion_tokens × output_price / 1_000_000)
```

## 🧠 УПРАВЛЕНИЕ КОНТЕКСТОМ

- При каждом запросе отправлять: `[system_prompt] + messages` (вся история сессии)

- Если превышает — предложить действия:
  1. Автоматически удалить самые старые сообщения (кроме `system`)
  2. Начать новый разговор (`/new`)

- Чистый, читаемый код
